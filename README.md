# YumBuddy — frontend preview

React-интерфейс для профиля ребёнка, дневника питания и воды, избранных рецептов
и плана на день. Данные этих экранов сохраняются в `localStorage` браузера.
Синхронизация между устройствами не реализована.

Подбор рецептов использует отдельную сетевую функцию. В этом репозитории нет
её серверной реализации или готового настроенного сервиса. Это прототип интерфейса;
медицинская точность, соблюдение ограничений питания и пригодность сгенерированных
рецептов здесь не подтверждены.

## Запуск интерфейса

Нужны Node.js и npm:

```sh
npm ci
npm run dev
```

Сборка: `npm run build`. Доступные исходники и зависимости — React, TypeScript,
Vite, Tailwind CSS, shadcn/ui, React Router, TanStack Query и Framer Motion.

## Настройка генерации

Создайте локальный `.env.local` по образцу `.env.example` и укажите параметры
своей совместимой функции:

```dotenv
VITE_SUPABASE_URL=
VITE_SUPABASE_PUBLISHABLE_KEY=
```

Клиент делает `POST` на `${VITE_SUPABASE_URL}/functions/v1/generate-recipe`,
передавая JSON и `Authorization: Bearer <VITE_SUPABASE_PUBLISHABLE_KEY>`.
Серверную функцию, её авторизацию и формат ответа необходимо настроить отдельно.
Без такой конфигурации генерация рецептов не готова к использованию.

Все `VITE_*` значения попадают в клиентскую сборку и доступны браузеру.
Используйте только клиентское значение, предусмотренное вашей функцией;
серверные секреты и ключи с привилегиями в эти переменные не помещаются.
Пустой пример не содержит настоящего адреса проекта или ключа.

## Какие данные передаются

При нажатии кнопки подбора рецепта клиент отправляет функции:

- имя и возраст ребёнка;
- аллергии и нежелательные продукты;
- выбранный приём пищи и максимальное время приготовления.

Профиль, дневник и избранное остаются в локальном хранилище, при этом выбранные
поля профиля участвуют в указанном сетевом запросе. Порядок дальнейшей обработки,
хранения и возможной передачи данных определяется настроенным вами backend.
Он не реализован и не проверен в этом репозитории.

Очистка `localStorage` удаляет браузерную копию. Она не удаляет уже отправленные
данные с внешнего сервиса. Перед использованием действительных профилей опишите
обработку данных в своём развёртывании.

## Статус и лицензии

Публикуются исходники frontend-прототипа. Работоспособность сторонней функции,
качество рецептов и готовность приложения к эксплуатации не заявляются.
Сторонние компоненты сохраняют свои условия распространения; отдельная лицензия
на собственный код проекта пока не выбрана. См. также `CHANGELOG.md`.
